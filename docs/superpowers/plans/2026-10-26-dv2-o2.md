# Decisions v2 · O2 Decision service, audit log and executors: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Managed requests are decided centrally by the org's decision service against an issuer-signed org policy
plus the member's own matrix; reviews are routed to org reviewers and signed on their enrolled phones; every decision,
review, admin action and lease lands in an append-only, hash-chained, checkpointed audit log that exports and verifies
offline; and an org executor (Reins Cloud mode first) re-evaluates every request on its own, runs exactly the approved
digest through the org's GitHub App and Google Workspace, and issues short-lived credential leases that deprovisioning
revokes.

**Architecture:**
- **Pure parts are shared crates**, so the decision service and the executor run the same code (08 R5):
  - `reins-proto::managed`: wire types, digests and every signed message (decision, review, roster, policy envelope,
    receipt, checkpoint, executor request).
  - `reins-policy::org`: Managed evaluation. It composes the org policy (issuer `Org` rules with reviewer sets, the org
    matrix, org facts, posture rules) with the member's matrix and stricter rules into P2's `matrix::Snapshot` and runs
    P2's `matrix::evaluate`, then turns the trace into obligations.
  - `reins-audit` (new crate): the export format and `verify`, the core of `reins-audit verify` (O5 packages it).
- **The server** (`src/api/reins/org/`) adds:
  - a KMS seam with per-tenant keys (issuer, decision service, data);
  - policy activation, signed by the issuer key after two Security admins' device signatures;
  - the signed roster;
  - the decision service and review routing;
  - the phone review API;
  - the executor API;
  - leases, checkpoints, retention and the console pages.

  The O1 admin event table *is* the audit chain: its hashes are kept, so O1's rows verify unchanged, and O2's kinds
  are appended to it.
- **The executor** (`crates/reins-executor`, a separate binary and trust domain) holds the managed credentials and
  pins the org's issuer and decision-service keys. Before acting it checks:
  - the countersignature;
  - the issuer-signed snapshot and roster;
  - the reviewers' device signatures;
  - the digest;
  - its own re-evaluation.

  It writes signed receipts. Reins Cloud runs one per tenant; Dedicated and Self-hosted run the same binary
  (`ExecutorMode`).

**Tech stack:**
- Rust 1.98.1: Rocket and Diesel (sqlite, mysql, postgresql) on the server; `ring` for Ed25519, ECDSA P-256, RSA
  PKCS#1, X25519 and AES-GCM; `x509-parser` for attestation chains; reqwest and tokio in the executor.
- UniFFI, Kotlin/Compose (Robolectric), Swift/SwiftUI.

## Global Constraints

- **Authorization invariants:**
  - mandatory deny and review win;
  - unknown facts never widen;
  - authority is proven, never claimed;
  - receipts and budgets are spent before effects.
- **Org guarantees:**
  - Auto never denies; only explicit rules deny (an org deny rule here).
  - "An org's Managed profile has no 'owner permits wider than org'" (02 §3.4): the member's permits are dropped, and
    their matrix only makes cells stricter.
  - The always-ask floor is a hard `require_review` (08 R4).
  - "A decision is valid only if it carries the reviewer's device signature over (request digest, decision, policy
    snapshot hash, time) [and] the decision service's countersignature. Executors check both before acting" (06 §3).
  - "Executors re-evaluate every request independently with the same engine library, against the policy snapshot
    signed by the org issuer key … An executor refuses if the decision service's verdict and its own differ; the
    snapshot isn't signed by the issuer; a review-required request lacks valid reviewer device signatures" (08 R5).
  - "Admin actions (policy activation, retention, executor config) require two Security admins' device signatures"
    (06 §3); an admin can't approve their own change (05 §3).
  - "A failing device can't approve, and its reviews route to others" (06 §6).
  - Requests carry their connection's profile; no request ever crosses profiles; the org never learns a Personal
    profile exists (08 R6).
- **Audit and isolation:**
  - Events form a hash chain per tenant; a signed checkpoint every 10 minutes (06 §5.2).
  - Tenant isolation (08 R12): per-tenant keys and data keys; an executor is bound to one tenant.
- **Retention:** request bodies are kept for none, 30 days or 1 year, 30 by default (06 §4).
- **Notifications** only for things a person must act on: an org reviewer's review and a change awaiting your
  signature. Never for Auto, denials or receipts.
- **Feature flag:** everything server-side is behind `REINS_ORGS_ENABLED` (default off). A Personal account's paths
  don't change.
- **Migrations:** sqlite, mysql and postgresql, matching `src/db/schema.rs`; MySQL ids use `utf8mb4_bin`.
- **Builds and tests:**
  - cargo `-j 4`, narrow `-p`, `CARGO_TARGET_DIR` inside the worktree;
  - tests with `XDG_CONFIG_HOME` and `TMPDIR` under `~/Documents/dev/tmp/dv2-o2/`;
  - pinned clippy: `PATH=$HOME/.rustup/toolchains/1.98.1-x86_64-unknown-linux-gnu/bin:$PATH cargo clippy -p <crate> -j 4 -- -D warnings`;
  - `cargo fmt`;
  - never `/tmp`.
- **Android and iOS:**
  - Android: `cd android && env -u ANDROID_SDK_ROOT ANDROID_HOME=$HOME/Android/Sdk ./gradlew --max-workers=4 :app:testFullDebugUnitTest`.
  - iOS: `scripts/ios-typecheck.sh`.
- **External services:** GitHub, Google and WorkOS are never called in tests (wiremock or fakes).
- **UI:** short copy, real icons (Material Symbols, SF Symbols), never emoji. The console follows O1's look
  (`console_pages.rs`).
- **Commits and PRs** never mention AI.

## Review Focus

1. **The server changes a request after it was approved** (a body edited in the database, or a different job sent to
   the executor). The executor must refuse: the digest of what it would run must equal the countersigned digest.
   Tests: `reins-executor` `verify::tests::a_body_that_is_not_the_approved_digest_is_refused` and the e2e
   `an_executor_runs_exactly_the_approved_digest`.
2. **The audit log is truncated, reordered or rewritten**, including a server that recomputes every hash. The verifier
   must fail on:
   - a gap or a swap;
   - a dropped tail (the signed export head no longer covers the last event);
   - a chain that does not extend a checkpoint obtained earlier.

   Tests: `reins-audit` `tests::{a_swap_fails, a_dropped_tail_fails, a_rewritten_chain_fails_against_an_earlier_checkpoint}`.
3. **A lease outlives deprovisioning:**
   - a token minted before the member is removed is revoked upstream by the executor within the minute;
   - no new lease is issued after removal.

   Tests: `leases::tests::deprovision_revokes_every_lease_of_the_member` and the e2e
   `deprovision_revokes_a_lease_upstream`.
4. **A reviewer approves through something other than an eligible, posture-passing enrolled device:** a revoked or
   rooted device, a device of another org, the requester themselves when `exclude_requester`, or one person counted
   twice. Each is refused. Tests: `reviews::tests::{a_revoked_device_cannot_approve,
   a_failing_posture_cannot_approve, the_requester_cannot_satisfy_an_org_review, one_person_counts_once,
   another_orgs_device_is_refused}`.
5. **Profile crossing:**
   - a Personal account's MCP call never reaches the decision service;
   - a Managed account's call never reaches its phone's relay;
   - one org's executor never sees another org's jobs.

   Tests: `managed_mcp::tests::only_managed_accounts_are_routed_to_the_org` and
   `executor_api::tests::an_executor_sees_only_its_own_tenant`.

    issuer isn't `Issuer::Org(org)` is refused by `OrgPolicy::validate()`.
  - `pub struct ReviewSpec { reviewers: Reviewers, quorum: u8 /* ≥1 */, distinct_persons: bool /* true */,
    exclude_requester: bool /* true */, class: ReviewClass, window_secs: u64 }`, with `ReviewSpec::owner()`
    (Requester, quorum 1, exclude_requester false, Instant, 120 s).
  - `pub enum Reviewers { Requester, Group(String), Role(Role), Members(Vec<String>) }`.
  - `pub enum ReviewClass { Instant, Deferred }`. Windows are clamped as in 03 §1: Instant ≤ 600 s, default 120;
    Deferred ≤ 7 days, default 4 h.
  - `pub struct PostureRule { screen_lock: bool /* true */, no_root: bool /* true */, attested: bool /* false */,
    min_os: BTreeMap<String, String>, min_app: Option<String>, max_age_days: u32 /* 30 */ }`.
  - `OrgPolicy::hash(&self) -> String` is the hex SHA-256 of `serde_json::to_vec`, the same rule as
    `Snapshot::hash`. `OrgPolicy::validate(&self) -> Result<(), String>` checks:
    - rule ids are unique and `[a-z0-9._@-]{1,64}`;
    - `quorum ≥ 1`;
    - `window_secs` is within its class bounds;
    - a `Review` rule carries `review`, and only `Review` rules do.
  - `pub struct MemberPolicy { matrix: Option<Matrix>, rules: Vec<Rule> }`. Only Deny/Review rules count; permits are
    dropped. `MemberPolicy::hash()`.
  - `pub struct ManagedRequest<'a> { org: &'a str, member: &'a str, connection: &'a str, tool: &'a str, args: &'a
    serde_json::Value, now: i64 }`.
  - `pub enum ManagedOutcome { Auto, Review, Deny }`.
  - `pub struct Obligation { id: String /* "cell" | "floor" | "level3" | "unreadable" | rule id */, spec:
    ReviewSpec }`.
  - `pub struct ManagedVerdict { outcome: ManagedOutcome, obligations: Vec<Obligation>, evaluation: Evaluation,
    member_policy: Option<String>, explain: String }`.
  - `pub fn analyze_request(tool: &str, args: &Value) -> Analysis`. It is `analyze_tool`, plus `git_lease` (`{repo,
    access}`), where read gives `DataRead{service:"git", resource: repo}` and push gives `DataWrite{service:"git",
    what:"Push to <repo>", lost:false}`.
  - `pub fn evaluate_managed(req: &ManagedRequest, org: &OrgPolicy, member: Option<&MemberPolicy>) -> ManagedVerdict`.
    It works in this order:
    1. **Analysis:** `analyze_request`.
    2. **Zone:** `request_zone` with `org.facts` and `Base{repo: args.repo for git_lease, bare_host: Some(GITHUB)}`.
    3. **Composed snapshot:**
       - the matrix is the stricter cell of `org.matrix` and `member.matrix` for every (zone, level), through
         `Matrix::loosens`;
       - the rules are the org rules plus the member's Deny/Review rules re-issued as `Issuer::Owner`;
       - no tasks;
       - the facts are `org.facts`.
    4. **`matrix::evaluate`** with `connection` and `seen_resource: false`.
    5. **Mapping:**
       - `Deny` → Deny;
       - `Auto` → Auto;
       - `Ask` → Review, with one obligation per hard `Why`: `Rule(id)` of an org rule takes its `review` spec, and
         a member rule, `Floor`, `Level3` or `Unreadable` takes `ReviewSpec::owner()`;
       - a soft cell (`Cell`/`FirstTime`) takes one `"cell"` obligation with `org.cell_review`.
  - `pub struct Approval<'a> { member: &'a str, groups: &'a [String], roles: &'a [Role], decision: bool /* approve */
    }`.
  - `pub fn obligations_met(obligations: &[Obligation], requester: &str, approvals: &[Approval]) -> Met`, where
    `pub enum Met { Yes, Waiting(Vec<String> /* obligation ids */), Denied }`. The rules:
    - a deny by an eligible reviewer → `Denied`;
    - each obligation counts eligible approvers: in `reviewers`, not the requester when `exclude_requester`, distinct
      persons;
    - with `distinct_persons`, one person satisfies at most one obligation, assigned greedily so the most
      constrained obligation (the fewest eligible approvers) is served first.

### Task 3: `reins-audit` export verifier

**Files:** Create `crates/reins-audit/{Cargo.toml,src/lib.rs,src/main.rs}` (Apache-2.0; deps: reins-proto, ring,
serde, serde_json, data-encoding). Modify the root `Cargo.toml` workspace `members`, `LICENSING.md` (row), and
`deny.toml` if it lists crates.

**Interfaces (Produces):**
- `pub struct TrustedKey { key_id: String, public: [u8; 32] }`.
- `pub struct Report { org: String, events: u64, first_seq: i64, last_seq: i64, head_hash: String, checkpoints: u64 }`.
- `pub enum VerifyError` (thiserror). Variants: `Parse { line: usize }`, `Gap { at: i64 }`, `BrokenLink { seq: i64 }`,
  `BadHash { seq: i64 }`, `MixedTenants`, `BadSignature { line: usize }`, `CheckpointMismatch { seq: i64 }`,
  `NoHead`, `HeadMismatch`, `DoesNotExtend { seq: i64 }`.
- `pub fn verify(input: impl BufRead, keys: &[TrustedKey], anchor: Option<&Checkpoint>) -> Result<Report,
  VerifyError>`. It checks:
  - each event links to the previous one, from `GENESIS_HASH` or from the export's first signed checkpoint;
  - each `Checkpoint` and `Head` envelope is signed by a trusted key over `envelope_message`, and its `(seq, hash)`
    equals the chain at that seq;
  - exactly one `Head`, last, covering the last event;
  - an `anchor` (from an earlier export or a witness) is on the chain at its seq with the same hash.
- `pub fn verify_envelope(env: &Envelope, keys: &[TrustedKey]) -> bool` is also used by the executor.
- **Binary:** `reins-audit verify <export.jsonl> --key <key_id>=<base64> [--anchor <checkpoint.json>]`. It prints the
  report, or the error and exit 1.

**Interfaces (Produces):**
- `pub struct Pins { org: String, issuer: TrustedKey, decision: TrustedKey }`.
- `pub struct ExecutorConfig { server: String, org: String, executor_id: String, mode: ExecutorMode, key_file:
  PathBuf, state_dir: PathBuf, pins: PinsConfig, github: Option<GithubConfig>, google: Option<GoogleConfig>,
  max_roster_age_secs: i64 /* 900 */ }` (TOML). It loads with `ExecutorConfig::load(path)`; secrets are files
  referenced by path (`SecretSource::File`) or env (`SecretSource::Env`).
- `pub enum Refusal { BadCountersig, WrongOrg, UnsignedPolicy, PolicyMismatch, UnsignedRoster, StaleRoster,
  DigestMismatch, VerdictDiffers { ours: String, theirs: String }, MissingApprovals(Vec<String>), BadApproval {
  member: String }, Expired, UnsignedMemberPolicy, Stale(String) }`, with `Refusal::reason() -> String`.
- `pub fn verify_job(job: &Job, pins: &Pins, policy: &Envelope, current: &Envelope, roster: &Envelope, now: i64) ->
  Result<Verified, Refusal>`. In order:
  1. **Countersignature:** `verify_envelope(decision, [pins.decision])` and `record.org == pins.org`.
  2. **Validity:** `now ≤ valid_until`.
  3. **Policy:** signed by `pins.issuer`, and its body hash equals `record.snapshot`; likewise `current`.
  4. **Roster:** signed by `pins.issuer`, the same org, and `now − issued_at ≤ max age`.
  5. **Digest:** `request_digest(org, member, connection, job.tool, &job.args) == record.digest`.
  6. **Member policy:** if present, signed by a roster device of `record.member`, and its hash equals
     `record.member_policy`.
  7. **Re-evaluation:** `evaluate_managed` at `decided_at`. Ours Auto and theirs Auto → ok. Ours Deny → refuse. Ours
     Review → every approval must:
     - verify over `review_message(org, Request, request, digest, Approve, snapshot, at)` with a roster device that
       `may_decide` and belongs to the approver;
     - then `obligations_met` must be `Yes`.

     Theirs Auto while ours is Review → `VerdictDiffers`.
  8. **Current world:** `evaluate_managed` against `current` at `now`. If it adds a Deny, or obligations the approvals
     don't meet, the result is `Stale(diff)` (03 §6).
