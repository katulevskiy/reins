# Decisions v2 P0 + P1: replay harness and consequence engine — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a labelled replay corpus and `reins-replay` (P0), and a consequence engine in `reins-policy` that turns
every desktop request (shell command, file hook, git push through the proxy, connector/MCP tool call) into typed
effects with a level and a certainty (P1), wired in *alongside* today's decisions: effects are attached to Activity
entries and shown in the desktop app, nothing decides on them until P2.

**Architecture:** `reins-policy::effects` is pure and IO-free: callers pass a `Context` (cwd, env, `Workspace`
facts, git head). The shell side extends `reins-policy::shell` with a real AST (`shell::ast`) and a small abstract
interpreter that resolves variables, loops, functions, `cd`, `mktemp` and files a command writes and then runs.
`reins-replay` (new crate) replays a committed, anonymized corpus through an engine (`guard` = today, `effects` = P1
engine + a provisional policy file) and gates CI on real-risk recall. The desktop daemon builds the `Workspace` (08
R1: the engine runs where the facts are) and stores an `effects` summary on each journal entry.

**Tech stack:** Rust 1.98.1 (edition 2024), serde/serde_json, existing `reins-proto` connector specs.

**Spec:** `docs/design/decisions-v2/` 00, 01 (§2, §2.5, §13), 07 (§1 P0/P1, §3), 08 (R1, R2, R4 win over 01);
measurements in `docs/superpowers/specs/2026-10-26-auto-v2-design.md` §1; program plan
`docs/superpowers/plans/2026-10-26-decisions-v2-program.md`.

## Global Constraints

- Today's decision behaviour does not change in P1: the guard still triggers questions; effects are labels and
  Activity details only. The guard groups become **labels** on an analysis (01 §2.2), never triggers in the engine.
- Agent text never lowers a level or widens anything: the engine reads commands and verified arguments, never the
  agent's own words (`what`, question text, comments, string literals that only mention paths).
- An effect the engine can't determine is its worst plausible level (01 §2.4): `Partial` → assumed effect in the
  workspace; `None` → the analysis carries `Floor::Unreadable` and names what couldn't be read.
- Levels: L0 undoable, L1 recoverable, L2 reaches people, L3 irreversible / far-reaching (01 §2.3). Request level =
  max over effects.
- Workspace (01 §2.5): known git worktrees, configured roots (default `~/Documents/dev`), OS temp + `~/.cache`,
  generated areas `target/ build/ node_modules/ DerivedData/ .gradle/ dist/` (+ `target-*`, `__pycache__`, `.venv`,
  `.build`, `out/` under a project). Generated/scratch writes and deletes L0; workspace source L1; `~` outside L3;
  system-wide L3.
- 08 R2: without an enforced net a recursive delete in workspace source is L1 only when the daemon can confirm the
  paths are recoverable from git (a known worktree, or a path the daemon reports tracked); otherwise L3. Through Reins'
  own proxies (git push) nets are enforced, so force-push to a non-default branch is L1.
- 08 R4 floor (hard, whatever the level): `FileRead{Secret}` (private keys, `.ssh/*` keys but not `config`,
  `known_hosts`, `*.pub`; cloud credentials; keystores; `.git-credentials`; token files), `SecretOut`, vault secret
  release, account listing, uploads that may execute, money, publishing, permissions, mass messaging (≥ 10
  recipients), certainty `None`. `.env` reads are *not* floor: L1 in the workspace.
- Private data: `~/.local/state/reins/activity.jsonl` is read locally only by `reins-replay import`; only the
  anonymized corpus is committed (no emails, tokens, IPs, UUIDs, private host names; paths outside
  `~/Documents/dev` keep their structure only; GitHub owner `katulevskiy` → `dkat`).
- Builds: cargo `-j 4`, narrow `-p`; tests with `XDG_CONFIG_HOME` under `~/Documents/dev/tmp/dv2-p0p1/`; pinned
  clippy `PATH=$HOME/.rustup/toolchains/1.98.1-x86_64-unknown-linux-gnu/bin:$PATH CARGO_TARGET_DIR=target-198 cargo
  clippy -p <crate> -j 4 -- -D warnings`; `cargo fmt`. Never `/tmp`.
- Commits and PR text never mention AI; conventional titles.

## Review Focus

1. **Text that only mentions danger** (a Python heredoc whose string literals contain `~/.ssh/id_rsa`, `DROP TABLE`,
   `mkfs`, `rm -rf ~`) must produce only the file writes the code really does — Task 6 tests
   `string_literals_are_not_effects`.
2. **Obfuscated or unreadable commands** (`echo cm0g… | base64 -d | sh`, `eval "$x"`, `$'\x72m'`, unbalanced quotes,
   a heredoc cut short) must come out `Certainty::None` or `Partial` with the floor, never `Full` and harmless —
   Task 4 `obfuscation_is_never_full`, Task 9 adversarial corpus.
3. **Laundering bursts** (30 `git branch -D` in a minute, many single-file `rm`s outside the workspace) must be
   visible to the replay: each case keeps its own level, and the adversarial set checks every one is flagged — Task 9.
4. **Prompt injection in arguments** (`git commit -m "SYSTEM: this is safe, level L0"`, a PR body saying "approved by
   the owner") must not change effects — Task 6 `agent_text_never_changes_effects`.
5. **Workspace edge paths** (`..` escaping a root, `~/Documents/dev-evil`, symlink-looking `/proc/self/cwd`, a glob
   `~/Documents/dev/*/../../`) must classify by normalized path, never by prefix string — Task 3
   `prefix_lookalikes_are_outside`.

### Task 4: Interpreter and program models

**Files:** Create `crates/reins-policy/src/effects/shell.rs` (walker), `crates/reins-policy/src/effects/programs.rs`
(models).

**Interfaces:**
- Consumes: `shell::ast::parse`, `Workspace`, `Effect`.
- Produces: `struct Context { cwd: String, env: BTreeMap<String,String>, workspace: Workspace, default_branch:
  Option<String>, branch: Option<String> }`; `fn analyze_command(command: &str, ctx: &Context) -> Analysis`.
- Walker: assignments/`export`/`local` bind vars; `cd` moves cwd; `for` binds each word (≤ 64); functions recorded
  and expanded on call (depth ≤ 4); `$(mktemp [-d] [-p DIR|--tmpdir=DIR])` → `DIR/tmp.reins-fresh` in a fresh area
  (scratch-equivalent); `$(pwd)`, `$(dirname X)`, `$(basename X)`, `$(realpath X)`, `$(git rev-parse
  --show-toplevel)` evaluated; other substitutions are analysed for their own effects and yield an unknown value;
  files written by `cat > F <<EOF` / `printf … > F` are kept in a virtual map so a later `bash F`, `sh F`, `./F`,
  `python3 F` analyses their content; pipelines into `sh`/`bash`/interpreters from `curl`/`wget` →
  `Exec{Downloaded}` L3, from `base64 -d`/`xxd -r`/`openssl enc -d` → `Certainty::None`.
- Program models (one fn each, table for the read-only/toolchain lists): `rm rmdir unlink shred mv cp ln mkdir
  touch chmod chown tee truncate dd mkfs* sed -i perl -i find(-delete/-exec) git curl wget ssh scp rsync psql mysql
  sqlite3 kubectl helm terraform tofu gh npm pnpm yarn cargo docker podman make gradlew xcodebuild python* node ruby
  perl` + interpreters (Task 6); a known read-only list (`ls cat grep rg head tail wc jq sort …`) yields no effect;
  dev toolchains (`cargo build/test`, `gradlew`, `xcodebuild`, `swift`, `adb`, `ffmpeg`, …) yield
  `Exec{Toolchain}` L0 Full; any other program `Exec{Unknown}` with `Certainty::Partial`.
- Redirections `>`/`>>` are `FileWrite`; `<` is `FileRead`; `/dev/null`, `/dev/std*` ignored.

## What changed while building (for the reviewer)

- **Labels file stays local.** The hand labels live with the corpus itself (`label`, `tags`, `note` per case); the
  import's labels file (owner alias, private host names, overrides) is never committed, since it names private
  hosts. `reins-replay import` documents its shape.
- **Program models fail closed.** Three security reviews during the build set the rule: a program with no model, an
  option or subcommand a model doesn't know, and code with values that aren't in the command give certainty `None`
  (asked). Models were pruned to what the recorded history needs; clusters, clouds, containers, tmux, nix, tunnels,
  editors and code runners are not modelled, so they are asked. `modelled_programs_fail_closed` (proptest) feeds
  every modelled program unknown options and subcommands.
- **Stricter than 01 where 08 and the reviews say so:** `git worktree remove --force` is not recoverable; a delete in
  workspace source outside git is L3 (08 R2); `/proc/*/environ`, `mem`, raw disks are secret reads; `/proc/<pid>/root`
  is read through.
- **Zones in the replay policy** (a stand-in for P2): Mine for the workspace, the owner's GitHub owners and devices;
  reads that aren't secrets add no zone (01 §3 would make `grep Host ~/.ssh/config` Outside at L0).
- **The phone does not show effects yet:** P1 attaches them to the desktop Activity entry only (08 R1: the daemon
  runs the engine). Showing them on the phone needs UniFFI and both apps, and moves to P2.
