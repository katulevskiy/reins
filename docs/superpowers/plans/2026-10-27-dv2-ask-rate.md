## The fixes

Every fix came with a corpus case that was asked before it (`corpus/nets.jsonl`, `corpus/ask-rate.jsonl`) and a risky
variant that is still asked; `tests/gate.rs` checks both sets (`nets_keep_recall_and_lower_the_ask_rate`,
`ask_rate_cases`).

1. **Nets: the leading commands, one-letter variables, loops** (`effects::nets`; 6 asks). Before, one construct
   off the allowlist anywhere in a script kept the whole script from being netted. Now:
   - Only the top-level commands up to the first one off the allowlist are netted. What follows runs after them (or,
     after `&`, in a shell they don't share), so it can't change what they run; it is not netted and keeps its own
     level. Anything off the allowlist before or beside a delete still stops the net.
   - A one-letter name may be set to a plain value (literal, quoted or a leading `~`; no glob or blank). No shell,
     git or Reins gives a one-letter name a meaning. It counts as known only when the assignment surely runs: first
     in a top-level list, not in a pipeline, not sent to the background. Then `$x` and `${x}` are plain words.
   - `for x in <plain words>; do …; done` with a one-letter variable, whose body passes the same rules. A name the
     body sets is unknown in it and after it.
   - `cd ~/…` targets are plan folders (`net run` refused them before, since `~` isn't literal).
   - The syntax tree now records `&&` vs `||`, `!` and a trailing `&` (`shell::ast`), so the proof compares them too.
   - Still asked: `PATH=…; rm …`, a loop over a glob, a loop naming a folder that is not a linked worktree, a delete
     after `cd X && B=…` (B may be the environment's), the tail deleting the trash, `eval` in the tail.
2. **The replay's known worktrees** (`corpus/context.json`; with fix 1, 3 asks). `reins-frost-fix`, `reins-next`,
   `reins-next-android`, `reins-sticky` and `zeron-wt/native-history-mcp` were linked worktrees when the requests
   ran: the recorded commands removed each one with `git worktree remove` and printed their success (`removed …`,
   `ok`). The desktop reads that from the folder itself.
3. **Hyprland's Lua dispatch** (`effects::programs`; 2 asks). `hyprctl dispatch "hl.dsp.window.<float|resize|center|
   move|focus>({ name = value, … })"`, with numbers, `true`/`false` or strings without quotes, backslashes, `;`, `,` or
   `[` as values and every word known, is a window action. Anything else in Lua (another function, a second
   statement, a concatenation, a long string, an unknown value) stays unread.
4. **Listing tools read no contents** (`effects::programs`, `effects::shell`; 1 ask). `ls`, `exa`, `eza`, `du`, `stat`,
   `realpath`, `readlink`, `basename` and `dirname` read names, sizes and links, so a secret's name is no secret read.
   Option files are still read as contents. **Recall fix:** `--files0-from=F` (`du`, `wc`, `sort`) now reads F, and
   for `wc`/`sort` the files it names; before, `du --files0-from=~/.ssh/id_ed25519` was Auto, though du prints the
   names back in its errors.
5. **A worktree the command adds is its repository** (`context::repo_at`; 3 asks). `git worktree add [opts] P` joined
   to a later `cd P` by `&&` only, at the top level, keeps the repository: the `cd` runs only when git made P (git
   fails on a folder that exists). Read from the syntax tree, so text in quotes adds nothing. `;`, `||`, `!` or a
   pipe in between, `git -C`, or an unknown option is still Unknown. **Recall fix:** a `cd` back into the cwd's
   repository after a leading `cd` elsewhere is now Unknown. Before, `cd ~/mine && …; cd <cwd> && git push origin x`
   took `~/mine`'s origin for the push (Auto; it is asked now).

Also: `reins-replay explain` takes `--policy`, so a case can be explained with nets.
