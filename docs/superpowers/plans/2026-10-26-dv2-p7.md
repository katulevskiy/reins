# Decisions v2 · P7 Guardianship and the Family tenant: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** guardianship in two strengths (08 R7):
- **Personal guardianship**, a fourth Circle arrangement on P6. It is cooperative and tamper-evident: notice periods,
  minor accounts, ward visibility, and guardian notices when the ward ends it, resets the account or changes the roster.
- **The Family tenant**, an O1 org tenant of tier `Family`, for enforceable guardianship. The guardians are the org:
  they provision the connections and the family's executor holds the credentials, so a child's agents act only through
  the family's managed connections (O2).

**Architecture:**
- **Part A (Personal, PR 1, on P6).**
  - A guardian arrangement is P6's arrangement record with `kind = Guardian` and a `GuardianTerms` block, signed by
    both parties after the safety code.
  - On the ward's phone it compiles to a hard review rule issued by `Issuer::Guardian(<arrangement id>)`. No permit and
    no Bypass satisfies it (02 §3 rule 3, 08 R3).
  - Ending runs from a signed `EndRequest`. Both phones compute when it takes effect, the rule stays until then, and a
    minor's ward needs the guardian's signed consent.
  - The server is blind, but it sees routing metadata (08 R8: accepted). It writes **guardian notices** for what it can
    observe: an end request, a pause, an account reset or deletion, a roster change. The guardian's phone verifies
    roster changes against the ward's roster chain. The rest it labels "reported by the server".
- **Part B (Family, PR 2, on O1 and O2).**
  - `Tier::Family` is an O1 tenant with no domain and no IdP. Members join by an invitation bound to an exact email,
    and only with a new account (08 R6: never capture a Personal account).
  - Guardians hold `OrgOwner`, `SecurityAdmin`, `ConnectionAdmin` and `Approver`. Children are `Member`s with a
    `minor` flag.
  - The family's policy is an O2 `OrgPolicy` built by `family_baseline()`: guardian reviews (`Role(Approver)`) on
    money, new people, publishing, permissions, L3 and the floor. O2's decision service evaluates it.
  - The child's accounts (a Google account, which Family Link supervises for under-13s, or GitHub) are connected by a
    guardian through an OAuth flow that the family's **executor** completes. The refresh token lives only in the
    executor; the server sees an authorization code it can't redeem.

**Tech stack:** Rust 1.98.1 (`reins-proto`, `reins-policy`, `reins-core`, server on Rocket/Diesel), UniFFI,
Kotlin/Compose (Robolectric), Swift/SwiftUI (XCTest). Apple `DeclaredAgeRange` and Google Play Age Signals, behind
one seam.

## Review Focus

1. **A guardian trying to coerce an adult**: marking them a minor, setting a notice over 7 days, or "permanent". The
   minor mark needs the ward's phone to accept it (with an age signal where the platform has one). Notice days are
   only 0, 3 or 7. Tests: `circle::tests::notice_days_are_0_3_or_7` (Task 1),
   `guardian::tests::a_guardian_cannot_mark_an_adult_minor_alone` (Task 4).
2. **The server forging or hiding guardian notices.**
   - It can drop or delay a notice, never forge a roster change. The guardian's phone checks the chain, and anything
     it can't check shows as "Reported by the server".
   - Test: `guardian::tests::roster_notices_are_verified_or_labelled` (Task 4).
3. **A ward escaping by reset or deletion in Personal mode.** The guardian is told before the account's rows go. Tests:
   `guardian_notices::tests::reset_notifies_every_guardian`, `a_deleted_account_notifies_before_erase` (Task 3).
4. **A guardian seeing beyond scope.**
   - Packets default to summary.
   - The digest holds only in-scope Auto decisions, as one line each.
   - Nothing reaches the guardian before the ward opts in.
   - Test: `guardian::tests::digest_is_off_until_the_ward_opts_in_and_stays_in_scope` (Task 4).
5. **A Family invitation capturing an existing account,** or being used by someone else. Invites bind to the exact
   email, are single use and expire. An address with an account is refused without saying whose it is. Tests:
   `family::tests::an_existing_account_is_never_captured`, `invites_are_single_use_and_bound_to_the_email` (Task 9).

### Task 1: Guardian terms in the protocol

**Files:** modify `crates/reins-proto/src/circle.rs` (P6) and `crates/reins-proto/src/pairing.rs`
(`PushKind::Guardian`, additive). Inline tests.

**Interfaces:**
- Consumes: P6 `Arrangement`, `ArrangementKind`, `Redaction`; `roster::RosterReason`.
- Produces:
  - `ArrangementKind::Guardian`, and `Arrangement.guardian: Option<GuardianTerms>` (serde default, skip none). It is
    required exactly when `kind == Guardian` (`validate()`).
  - `struct GuardianTerms { notice_days: u8, minor: Option<MinorMark>, digest: bool }`; `digest` is set only by the
    ward. `pub const NOTICE_DAYS: [u8; 3] = [0, 3, 7];`.
  - `struct MinorMark { by_guardian_at: i64, ward_accepted_at: i64, source: AgeSource }`, with
    `enum AgeSource { Platform { kind: AgePlatform, upper: Option<u8> }, GuardianAndWard }` and
    `enum AgePlatform { AppleDeclaredAgeRange, GooglePlayAgeSignals }`.
  - `struct EndRequest { arrangement: String, by: EndBy /* Ward | Guardian */, requested_at: i64, nonce: String, sig:
    String }`, signed by the requester's approval-device key over `end_request_bytes` (domain
    `reins/guardian-end/v1\n`).
  - `fn effective_at(terms: &GuardianTerms, req: &EndRequest) -> Option<i64>`:
    - Guardian → `requested_at` (the helper leaves at once);
    - Ward, adult → `requested_at + notice_days × 86 400`;
    - Ward, minor → `None` (needs consent).
  - `struct EndConsent { arrangement: String, request_hash: String, at: i64, sig: String }`, signed by the guardian.
    With it, the end takes effect at `at`.
  - `enum GuardianNoticeKind { EndRequested, Ended, Paused, AccountReset, AccountDeleted, RosterChanged { reason:
    RosterReason, epoch: u64 }, Suspended }`.
  - `struct GuardianNotice { id, arrangement, ward_account, kind, at, by_server: bool }`.
  - `GuardianTerms::validate()` refuses `notice_days ∉ NOTICE_DAYS`, and a `minor` without `ward_accepted_at`.

**Interfaces:**
- `pub enum OAuthProvider { Google, Github }` in `reins_proto::managed`. `pub struct ConnectJob { member: String,
  provider: OAuthProvider, phase: ConnectPhase /* Begin | Finish { code: String, state: String } */ }`.
- **Begin** (a guardian with `ManageConnections`, in the console):
  - the server queues `Connect{Begin}`;
  - the executor makes a PKCE verifier and a `state`, keeps them in `state_dir/connect/<state>` (10 min), and returns
    the authorization URL in its receipt. It holds the OAuth client id and secret (`ExecutorConfig.user_oauth`);
  - the server redirects the guardian's browser there.
  - Google scopes are the existing Gmail and Calendar connector scopes; GitHub's are `repo` and `read:user`.
- **Finish:** the provider redirects to `GET /reins/org/family/oauth/callback?code&state`. The server queues
  `Connect{Finish}` and never redeems the code: it can't, without the verifier and the client secret. The executor
  exchanges it and stores the refresh token in `user_tokens.json`, encrypted with AES-256-GCM under a key derived by
  HKDF from its key file (info `reins/user-tokens/v1`), file mode 0600. It receipts `{account}`, and the server marks
  the row `connected`.
- `UserOAuthConnector` implements O2's `Connector`. `run(member_email, tool, args)` refreshes that member's token (and
  only that member's) and calls the same Gmail, Calendar or GitHub endpoints as O2's connectors, with the same minimal
  results.
- Revoke: a guardian's revoke queues `Connect`-revocation. The executor revokes upstream (Google `oauth2/revoke`;
  GitHub `DELETE /applications/{client_id}/grant`) and deletes the token. Deprovisioning a member revokes theirs (O2's
  revocation queue).
- Child agents pair to the Family profile (O1's picker), so R6 holds: a Personal connection of the same person never
  reaches the family's tools.
