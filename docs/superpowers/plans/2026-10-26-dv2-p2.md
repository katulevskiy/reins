# Decisions v2 P2: context graph, zone/level matrix, no auto-deny — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal (as built: the matrix decides by default once Auto's setup is done; see the end):** zones from verified facts (the context graph), the zone × level matrix evaluated per 08 R3 with the 08 R4
floor, Auto that never denies, the setup flow ("when you turn on Auto, it guides you") on both phones and the desktop,
"Auto needs information" question cards, "Ask me next time", and the replay gate on the matrix decision. In
production the matrix runs **in shadow** behind `matrix_decides` (default off): today's deciders keep deciding and
what the matrix would have decided is recorded on the entry. The coordinator flips the default after the P1
hardening PR (`dv2/p1-hardening`) merges.

**Architecture:** two new pure modules in `reins-policy`: `context` (zones from a `Facts` snapshot; unknown is
Outside) and `matrix` (a `Snapshot` of cells, rules and tasks; `evaluate` composes deny, hard obligations, soft cells
and OR-ed permits bounded by tasks). `reins-replay` drops its stand-in zones and policy and replays through them.
The phone (`reins-core`) keeps a sealed snapshot, gathers verified facts from connected accounts and its own sent
history, evaluates every connector and git-proxy request in the Autopilot pass and stores the evaluation on the
suggestion and the Activity note; with `matrix_decides` on, the matrix replaces the model's verdict in Auto and the
model is only an approve/ask sanity check. The desktop daemon (08 R1: the engine runs where the facts are) evaluates
hook commands with its own facts (`[auto]` in its config) and records the shadow on the journal entry; with
`matrix_decides` on, it allows matrix-Auto commands locally and asks the phone for matrix-Ask ones. The apps add the
setup flow, question cards and the Activity line.

**Tech Stack:** Rust 1.98.1 (edition 2024), serde, `sha2` (snapshot hash), UniFFI; Kotlin/Compose; Swift/SwiftUI;
gpui (desktop app).

**Spec:** `docs/design/decisions-v2/` 01 (§3, §4, §6, §7, §9), 02 (§3, §5), 07 (§1 P2, §2), 08 (R1, R3, R4, R6 win
over 01/02); program plan `docs/superpowers/plans/2026-10-26-decisions-v2-program.md`; P1 plan
`docs/superpowers/plans/2026-10-26-dv2-p0-p1.md` ("What changed while building").

## Global Constraints

- **The matrix decides nothing in production until hardening merges:** `MATRIX_DECIDES_DEFAULT = false` in
  `reins-core` and `[auto] matrix_decides = false` on the desktop. Off: every decision is exactly today's, minus
  auto-deny; the evaluation is recorded (shadow). On: the matrix decides as below.
- **Auto never denies.** Only explicit rules deny: Lockdown, "never" rules (owner `Deny` rules), org deny, repo deny.
  A model "deny" becomes Ask in Auto and Overnight, in shadow mode too (it only asks more).
- **08 R3:** matrix cell Ask = soft (`review_by_default`): any one qualifying permit satisfies it (OR). Fixed
  overrides (the R4 floor, L3, certainty None), repo/org/Circle/guardian `review` rules and "Ask me next time"
  exceptions are hard: no permit satisfies them. Tasks and delegations are AND bounds on their own permits.
- **08 R4 floor** (`Analysis.floor` non-empty, which includes `Unreadable`) is a hard review in Auto and Overnight.
  Only Bypass covers the owner's own obligations (unchanged existing path).
- **01 §4 default matrix (Personal):** Mine `Auto Auto Auto Ask`; Friends `Auto AskFirst Auto Ask`; Work `Auto Ask Ask
  Ask`; Outside `Ask Ask Ask Ask` (L0..L3). L3 is never Auto whatever the cell (fixed override).
- **Unknown never widens:** an owner, domain, person, host or chat not in `Facts` is Outside; an empty or unparsable
  resource is Outside; `Area::Home | Area::System` writes and deletes are Outside. Zones come from `Facts` only, never
  from agent text; lookups are exact (lowercased ASCII), never prefix or fuzzy.
- **Reads add no zone** (as the P1 replay stand-in decided): only what a request changes or reaches sets the zone.
- **08 R6:** the snapshot is per profile (Personal on the phone; Managed profiles are O1's): a request is evaluated
  only against its own connection's profile, and nothing about a Personal profile leaves the phone except the
  desktop's own `[auto]` facts.
- **Loosening needs the owner check** (02 §5): moving a fact toward Mine, a cell from Ask to Auto, finishing setup and
  answering a question with anything but Outside call `OwnerCheck`. Tightening is immediate.
- **Notifications:** only for the owner's action. Question cards are listed with pending items but never notify on
  their own; automatic decisions never notify (PR #211).
- **Private data:** facts (people, domains) are sealed with the data key on the phone; the server never sees them.
- **UI:** minimal text, real icons (SF Symbols / Material Symbols), never emoji, the Next look (`design/next/`).
  Question cards reuse the approval card shell.
- **Builds:** `source ~/Documents/dev/tmp/dv2-p2/env.sh` (own `CARGO_TARGET_DIR`, `XDG_CONFIG_HOME` and `TMPDIR`
  under `~/Documents/dev/tmp/dv2-p2/`, no swiftly linker); cargo `-j 4`, narrow `-p`; pinned clippy
  `PATH=$HOME/.rustup/toolchains/1.98.1-x86_64-unknown-linux-gnu/bin:$PATH CARGO_TARGET_DIR=target-198 cargo clippy
  -p <crate> -j 4 -- -D warnings`; `cargo fmt`; never `/tmp`.
- **Git:** conventional commits, no AI mention, `git -c commit.gpgsign=false commit` if signing hangs.

## Review Focus

1. **Agent text names a lookalike** (`dkat-evil/reins`, `dkat.org`, `DKAT` with a Cyrillic letter, a recipient
   `me@gmail.com.evil.io`, a host `localhost.evil.io`): exact lowercase lookup only, so each is Outside — Task 1
   `lookalikes_are_outside`.
2. **A multi-party request with one unknown party** (an email to the owner and a stranger; a push of two refs to two
   repos): the least trusted zone wins — Task 1 `one_outside_party_makes_it_outside`.
3. **A permit trying to satisfy a hard obligation** (an accepted repo permit or a task covering an L3 delete, a floor
   secret read, or an "Ask me next time" exception): still asked — Task 2 `permits_never_satisfy_obligations`.
4. **A task permit outside its envelope** (another connection, above its ceiling, after its end, another zone): no
   effect — Task 2 `tasks_bound_their_permits`.
5. **Profile crossing:** a connection's request is evaluated with its own profile's snapshot only, and a desktop
   entry never carries phone facts — Task 6 `matrix_uses_the_connections_profile_only`, Task 8
   `desktop_facts_are_its_own`.

  (returns `false`) a domain in `PUBLIC_MAIL_DOMAINS` (`gmail.com googlemail.com icloud.com me.com mac.com
  outlook.com hotmail.com live.com yahoo.com proton.me protonmail.com aol.com gmx.com yandex.ru mail.ru`) and any key
  with non-ASCII characters or empty.
- `#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)] pub enum FactKind { Owner, Repo,
  Domain, Person, Host, Chat }`.
- `#[derive(Clone, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)] pub struct Unknown { pub kind: FactKind, pub
  key: String }`.
- `pub struct Resolved { pub zone: Zone, pub unknown: Vec<Unknown>, pub resource: Option<String> }`.
- `pub fn repo_zone(facts: &Facts, repo: &str) -> (Zone, Option<Unknown>)`: `owner/name` (any of
  `https://host/o/n(.git)`, `git@host:o/n`, `github.com/o/n`, `o/n`) → `repos["o/n"]`, else `owners["o"]`, else
  Outside with `Unknown{Owner, o}`; unparsable → Outside, no unknown.
- `pub fn party_zone(facts: &Facts, channel: &Channel, party: &str) -> (Zone, Option<Unknown>)`: email/calendar:
  `own_addresses` → Mine, `people` → its zone, `domains[domain]` → its zone, else Outside + `Unknown{Person, addr}`;
  Telegram/SMS: `"me"`/`"self"`/`"saved messages"` → Mine, `chats`/`people` → zone, else Outside + `Unknown{Person}`;
  GitHub → `repo_zone`; `Other` → Outside.
- `pub fn host_zone(facts: &Facts, host: &str) -> (Zone, Option<Unknown>)`: `effects::local_host` → Mine, `hosts` →
  zone, else Outside + `Unknown{Host}`.
- `pub fn request_zone(a: &Analysis, facts: &Facts, base_repo: Option<&str>) -> Resolved`: max over effects:
  `FileWrite`/`FileDelete` by area (`Generated|Scratch|Source|Unknown` → Mine, `Home|System` → Outside,
  `Remote(h)` → `host_zone`); `GitPush`/`GitRefDelete` → `repo_zone` (a repo without an owner, e.g. `origin`, is
  `base_repo`'s zone, else Outside); `Message` → every party; `Network{Write|Connect|UploadExecutable}` →
  `host_zone`; `Infra{local:false}`, `Exec{Downloaded}`, `Publish` → Outside; `Permission{resource}` →
  `repo_zone(resource)`; `SecretOut` → Outside; reads, `DataRead`, `DataWrite`, `SecretUse`, local `Exec`/`Infra`,
  `Money`, `Unknown` add no zone (their floor/level decides). No contributing effect: `base_repo`'s zone if given,
  else Mine. `resource`: the single repo (`o/n`), else the sorted recipients joined by `,`, else the host; `None` if
  none. Unknowns are deduplicated.

## What changed while building (for the reviewer)

- **The matrix decides by default (changed after the hardening PR #220 merged).** `MATRIX_DECIDES_DEFAULT = true` on
  the phone, in Auto, once the owner finished Auto's setup (07 §2: until then Auto behaves as before, minus auto-deny);
  `set_matrix_decides(false)` returns it to shadow. The desktop's `[auto] matrix_decides` stays off: hook-level
  deciding uses the computer's own unsigned facts (no signed snapshot from the phone yet, 08 R1), and with no facts set
  every push to `origin` of an unzoned owner would be asked.
- **Replay numbers (on the hardened engine, the matrix deciding):** 814 recorded requests, 51 asks (6.3%); developer
  requests 738, 44 asks (6.0%, the same as the stand-in after #220); real-risk recall 209/209; labelled risks Auto 0;
  needs-a-person 218/218 asked; known false positives asked 0/75; adversarial 250, 203 asked. Before #220 the same
  matrix gave 37/738 (5.0%). Every developer ask is a hard obligation (18 L3 deletes in Mine, the rest unreadable or
  the floor), so P2's "≤ 5%" line now waits for P3's nets (trash makes those deletes L1). The gate ratchets
  `developer_ask_rate` in `baseline.json`.
- **`origin` is the worktree's repository.** A command's `git push origin …` and `gh` calls that name no repository
  ("this repository") take the zone of the repository the agent works in: the desktop reads the worktree's
  `[remote "origin"] url` from its files; the replay corpus records it as `context.origin`. Without it they're
  Outside. The stand-in oracle test (`tests/stand_in.rs`) shows the graph and P1's stand-in agree on every recorded
  case.
- **Unresolved paths are Mine** (01 §2.4: "assumed … in the workspace's zone"). Making them Outside added 12 asks
  with no real risk among them; their level and certainty already carry the doubt.
- **GitHub orgs are not fetched at setup.** The setup proposes from what the phone has without a network call: the
  connected GitHub login (Mine), Gmail addresses (Mine), their non-public domains (Work, proposed), people the owner
  sent mail to by hand in the last 90 days (Friends, proposed; a send by Bypass or Auto proposes nobody), and GitHub
  owners seen in recent requests (proposed Outside, so they're listed with their counts). Orgs come in as questions
  the first time a request names one. Zone proposals by the model (01 §3, §6.4) aren't built; proposals are
  deterministic.
- **Proposals decide nothing.** They live apart from `Facts` until the owner confirms them (finishing setup, a zone
  change, or answering a question); until then the party is Outside.
- **The desktop has no deny rules.** Its `[auto]` holds facts and a matrix only; deny and review rules are the
  phone's. `on_deny_rule_denies` was dropped from Task 7; a matrix Auto on the desktop returns no opinion to the
  harness (its own permission flow still runs) rather than an explicit allow, and is put in Activity only when the
  guard would have asked.
- **The matrix decides only in Auto.** With `matrix_decides` on, Overnight keeps today's path (Overnight v2 is P5).
  Overnight's explicit "If something is too risky: deny it" stays until P5 replaces it with parking; every learned
  deny (Auto's and Overnight's) is gone now, independent of the switch.
- **Policy records:** Decisions v2 rules are evaluated by `reins_policy::matrix` with the R3 semantics, next to the
  existing authorization runtime (which still runs first and stays hard); compiling them to `PolicyRecord v2` (02 §2)
  is left to O2/O4.
- **The snapshot is per account on the phone** and isn't synced to other phones or signed for the desktop (08 R1's
  signed snapshot): the primary phone decides, viewers don't. A handover to a new primary starts with the default
  snapshot until its setup runs. The signed snapshot is needed before the desktop's `matrix_decides` is turned on.
- **"Ask me next time"** writes the exception rules (permanent for the resource, 24 h for the zone and kinds); it
  isn't yet a 3× training example for the model (the existing "This was wrong" still trains).
