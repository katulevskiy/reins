# Decisions v2 P5: Overnight v2 and tasks. Implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Overnight becomes "Auto while you're away": what Auto would ask is **parked** (a Deferred ticket, the agent
carries on), the owner gets **one morning digest** grouped by agent and task, nothing is ever denied automatically,
people are stricter and the owner's own L1 work is looser. **Tasks** let an agent (or the owner, or Overnight) open a
bounded envelope inside which soft Ask cells become Auto, never past its ceiling and never over a hard obligation.

**Architecture:**
- `reins-policy::matrix` gains the Overnight overlay (`Input.overnight`, `Outcome::Park`) and the full task envelope
  (`Task::holds`: connection, repos, branch globs, path roots, people, operations, budget, duration, ceiling ≤ L2). Pure
  and deterministic; the replay runs it and reports morning decisions per agent-night.
- `reins-core` decides Overnight with the matrix (once Auto's setup is done; before that, today's Overnight path minus
  the deny), parks every wait as a P4 ticket with a window that ends `expiry` after the morning, and serves the digest.
  Tasks are sealed records next to the P2 snapshot, injected into it at evaluation time, with uses spent before the
  effect.
- Agents propose tasks through two new connector tools (`reins_task_propose`, `reins_task_end`; desktop:
  `desktop_task_propose`, `desktop_task_end`), so the server lists, bounds and relays them with no new route. The
  phone shows the envelope on the card; the owner can narrow it before approving (owner check).
- Apps: the Overnight sheet loses "If something is too risky: deny it" and gains "Expires after"; the Waiting-for-you
  inbox groups by agent and task with **Approve all for this task**; a task card; a live task chip with Stop; one
  local digest notification at the morning time.

**Tech Stack:** Rust 1.98.1 (edition 2024), serde, UniFFI; Rocket server (unchanged routes); Kotlin/Compose;
Swift/SwiftUI.

**Spec:** `docs/design/decisions-v2/01-decision-engine.md` §4, §10–§12; `02-policy-and-authority.md` §1, §3, §9;
`03-decision-lifecycle.md` §1, §5.2, §7; `07-roadmap.md` §1 (P5), §2; `08-review-resolutions.md` R3, R4, R12 (08 wins).
Builds on `2026-10-26-dv2-p2.md` (matrix, snapshot) and `2026-10-26-dv2-p4.md` (tickets, inbox).

## Global Constraints

- **Overnight never denies.** Only explicit rules deny (Lockdown, owner "never" rules, repo/org deny). `OvernightRisky`
  and `set_overnight_when_risky` are removed from the core and the apps (07 §2: "Overnight's 'deny if too risky': P5:
  removed; parked instead").
- **Overnight matrix (01 §11):** L2 whose zone is Work or Outside is always parked (hard: no permit, no task satisfies
  it); L1 in Mine and Friends is Auto (an Overnight permit, R3: it satisfies soft cells only); L3 is always parked;
  everything else follows the owner's matrix, rules and tasks. Every Ask becomes Park.
- **Parking (R3 "a separate `park` effect"; R12):** in Overnight the owner's own reviews are Deferred, the 08 R4 floor
  included (still hard, still the owner's, only the class changes). A park is a P4 ticket with
  `deadline = max(morning, now) + expiry`, `expiry` default **12 h** (the owner's setting: 1–48 h), clamped to P4's
  7-day max. `morning` = the Overnight's end when it has one, else now. The agent is told "Parked until morning".
- **Notifications:** parking never notifies. One local notification at the morning time lists what waits ("3
  waiting: 1 from Claude Code (Fix CI), 2 from ChatGPT"), only when something waits. P4 reminders for a parked item
  start only after the morning. Task end, task start by the owner, and automatic decisions never notify.
- **Batch (03 §5.2):** "Approve all for this task" approves only items whose matrix outcome was soft (not hard) and
  below L3. Hard items are listed and decided one by one.
- **Tasks (01 §12, 08 R3):** an AND bound. A task permit holds only for its connection, before `not_after`, with uses
  left, at level ≤ ceiling, and every repo, branch, path, person and effect kind of the request inside the envelope.
  Ceiling default **L1**, or **L2** when every repo listed is Mine; **L2** at most; L3 is never a ceiling. People: none by
  default (a request reaching a person needs that person listed). Duration 15 min to 24 h. One live task per
  connection (a new one ends the old one).
- **Agent text never widens anything:** a proposal is bounded by the tool spec, the owner sees and may only narrow it
  on the card, and the stored envelope is what the owner approved. The agent's `reason` is shown labelled as the
  agent's and is never read for policy. A proposal is owner-only: never decided by Auto, Overnight or Bypass.
- **Ending a task only narrows:** `reins_task_end` and Stop apply at once and are never asked.
- **Builds:** `source ~/Documents/dev/tmp/dv2-p5/env.sh` (own `CARGO_TARGET_DIR` in the worktree, `XDG_CONFIG_HOME` and
  `TMPDIR` under `~/Documents/dev/tmp/dv2-p5/`); cargo `-j 4`, narrow `-p`; pinned clippy
  `PATH=$HOME/.rustup/toolchains/1.98.1-x86_64-unknown-linux-gnu/bin:$PATH cargo clippy -p <crate> -j 4 -- -D warnings`;
  `cargo fmt`; never `/tmp`.
- **UI:** a few words plus buttons, details behind (?) or More; SF Symbols / Material Symbols, never emoji; the Next
  look (`design/next/`). Copy: "Parked", "Approve all", "Expires after", "Task", "Stop", "Up to: Recoverable".
- **Git:** conventional commits, never mentioning AI; `git -c commit.gpgsign=false commit` if signing hangs.

## Review Focus

1. **Agent text in a proposal** (a `reason` that says "ceiling L3", a repo `*`, a person glob, a title with bidi
   characters): the envelope is only the typed fields within the spec's bounds; `*` alone, a bare `**`, and L3 are
   refused; bidi/invisible characters show, never act — Task 4 `proposals_are_bounded_and_text_is_inert`.
2. **A task permit outside its envelope** (another connection, a repo or branch not listed, a path outside its roots,
   an unlisted recipient, past its end, no uses left, above its ceiling): Ask/Park — Task 1
   `task_envelope_is_an_and_bound`.
3. **A task or Overnight permit over a hard obligation** (floor secret read, L3 delete, an owner Review rule, L2 to a
   Work person in Overnight): still hard — Task 1 `overnight_and_tasks_never_satisfy_hard`.
4. **Overnight auto-denying anything** (a model sure to deny, a tripwire, catastrophic risk, the legacy path without the
   matrix): parked, never denied; only a Deny rule denies — Task 3 `overnight_never_denies`.
5. **Batch approving across L3 or a hard item**, and a digest that notifies when nothing waits — Task 3
   `approve_all_skips_hard_and_l3`, `digest_is_none_when_nothing_waits`.

## What changed while building (for the reviewer)

- **Built on a local merge of P2 (#224) and P4 (#214/#215)**, neither merged when this was built. Two base fixes
  were needed and are P4's to make on its rebase: O1's `2026-10-26-000000_reins_orgs` and P4's
  `2026-10-26-000000_reins_tickets` migrations had the **same version**, so Diesel ran only one of them (the org
  tests failed with "no such table: reins_orgs"); P4's ticket migration is renamed `2026-10-26-100000`. And P4's
  `wake_phone` built a `PushMessage` without O1's `p` field.
- **The parked/task fields are on `PendingItem`, not `TicketView`:** an item is parked (and must stay quiet) before
  its ticket exists. `parked_until`, `task_id`, `task_title`, `batchable`, `task_proposal`.
- **Parking is two steps:** the pass marks the suggestion (`Suggestion.parked`), then `ap_park_waiting` (right after
  the pass) signs the Deferred event with the morning window and the note "Parked until morning". A park that can't
  become a ticket (an older server, no session) waits as an Instant item, still quiet until the morning, and is tried
  again by the next pass; P4's overdue sweep leaves it alone.
- **The morning is the Overnight's end** (the time the owner set when starting it). An Overnight without an end has no
  digest notification: the digest shows when Reins is opened (01 §11 "or when you open Reins"), and parks expire 12 h
  (the setting) after they were parked.
- **The floor parks in Overnight** (08 R4 says Instant by default; 08 R12 makes the owner's own reviews Deferred in
  Overnight). Still hard: never batch-approved, never satisfied by a task.
- **Until Auto's setup is done, Overnight keeps the risk gate** (07 §2: "until they finish them, Auto behaves as
  today, minus auto-deny"), with every catastrophic hold and every model deny parked instead of denied.
- **A task is a permit by itself** (`Why::Task`), not only through an `Issuer::Task` rule. An Outside request is
  covered only when the envelope names its repos or people; an emptied list on narrowing is refused (it would mean
  "any").
- **A task starts only from its card** (`approve_task`, owner check first); the plain approval of a proposal is
  refused. Proposals are never automatic, Bypass included (`owners_alone`).
- **Services as a separate envelope dimension** (01 §12) aren't built: operations (effect kinds) plus resources
  (repos, people) bound the same thing.
- **Tasks don't cover hook-level shell commands:** the phone doesn't evaluate a computer's hook questions (08 R1);
  the daemon would need the phone-signed snapshot (not built). Tasks cover connector calls, MCP tools and git pushes
  through the desktop proxy.
- **Desktop:** the tools are `desktop_task_propose`/`desktop_task_end` (ops `desktop_propose`/`desktop_end`: a
  service and op name one tool). A hook's first deferral message may lack the night note (the relay's immediate
  deferral carries only the ticket); later polls of the ticket carry it. The desktop accepts only the exact note text,
  so the server can't put words in front of the agent.
- **Apps:** starting a task from the mode sheet (`start_task`) has a core API and fakes but no screen yet.
- **Replay:** an agent-night is one agent's requests on one UTC day of the corpus (the corpus is daytime work, so this
  is pessimistic). 55 parks (51 hard) over 24 agent-nights; morning decisions mean 2.17, median 1, max 12; risks run
  0; denied 0. The success line (≤ 3 per agent-night) holds on the mean and the median, not on every night: the worst
  nights are many hard L3 deletes in Mine that P3's nets make L1 (and so Auto overnight).
- **A flaky test:** `tests/engine.rs::cancelling_sync_after_the_server_delivered_still_parks_the_item` (a 600 ms
  timing) fails under load on the P2+P4 base as well (5 of 6 runs there); not changed here.

## Review round (one round, fixed in `fix/p5-review`)

1. **A use is spent only while the task is live:** a Stop, an end or an expiry between the evaluation and the spend
   leaves the request waiting (`ap_task_count`).
2. **Every change to the task records is one store transaction** (`Store::meta_update_sealed`: this process's
   connection held, `BEGIN IMMEDIATE` against the notification extension). The same goes for the owner's narrowed
   edits.
3. **`PendingItem.parked`:** an Overnight without an end parks until now, so the apps key "never notify" on the flag,
   not on `parked_until`.
4. **Task bounds:**
   - a task names at least one of repos, people, folders or kinds, unless the owner chooses **Any** (`TaskView.any`);
     an agent can't propose Any;
   - once branches or folders are named, a kind of effect no list bounds is outside the task (reads aside);
   - an agent's ceiling starts at the default for its repositories (`requested_ceiling` keeps what was asked), and
     the owner may raise it up to that.
5. **"Approve all" is a positive flag** (`Suggestion.batchable`), set only where the matrix asked softly below L3.
   A closer look, a risk hold, a tripwire, a pause, the floor and a computer's question are never batched.
6. **"Approve all" approves with the screen's default selection** (`Subject.choice`); purchases and standing
   permissions are left out.
7. **Overnight's looser L1 needs a planned net** (`Input.netted`: the analysis is a `NetPlan.after` that runs first).
   - The desktop's netted evaluation sets it. It evaluates with `overnight: false` (the computer doesn't know the
     phone's mode at hook time), so the relief can't fire there yet.
   - The phone plans no nets for its own requests, so on the phone a Friends L1 follows its cell (Ask first, so it
     parks). A Mine L1 is Auto by its cell anyway.
