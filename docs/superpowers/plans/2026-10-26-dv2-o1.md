# Decisions v2 · O1 Organizations foundation: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a Reins organization tenant (Team, Business, Enterprise) with verified domains, org sign-in (WorkOS SSO, or
Google Workspace / GitHub org for Team), SCIM through WorkOS Directory Sync, roles with two-person admin actions,
deprovisioning in under 60 s, device enrollment with attestation and posture, a minimal admin console, and a Managed
profile next to the Personal one on Android, iOS and the desktop.

**Architecture:**
- **Server.** The tenant *is* a Vaultwarden organization: `organizations` is the tenant row, `users_organizations` the
  membership (status `Accepted`, type `User`, `external_id` = the WorkOS directory user), `groups`/`groups_users` the
  SCIM groups (`external_id` = the directory group). Reins adds side tables keyed by the org uuid: tier and identity,
  domains, roles, pending admin changes, enrolled devices, and an append-only, hash-linked admin event table that O2
  migrates. All code lives in `src/api/reins/org/*.rs` and `src/db/models/reins_org*.rs`. Everything is behind
  `REINS_ORGS_ENABLED` (default off), so merging changes nothing on the hosted server.
- **A Managed profile is a separate Reins account** (the work email, e.g. `dana@acme.com`) that is a member of an org.
  WorkOS AuthKit keeps one user per email, so the work account and the Personal account (`dana@gmail.com`) never share
  an identity. On the phone each profile runs its own `ReinsCore` on its own data directory, wrapped by its own
  Keystore alias / Keychain item, with its own notification channels; Activity is separate because the stores are.
- **Shared pure logic** (roles, capabilities, domain rules, posture, remote routing) is in `reins-proto::org`, so the
  server, core and desktop agree. Core adds `profiles` (the device's profile registry, a UniFFI object) and org calls.
  The desktop holds one identity and session per profile and routes git by the remote's owner.

**Tech stack:** Rust 1.98.1 (Rocket, Diesel for sqlite/mysql/postgresql, hickory-resolver, psl, ring), UniFFI,
Kotlin/Compose with Robolectric tests, Swift/SwiftUI with XCTest (CryptoKit Secure Enclave, DeviceCheck App Attest).

**Spec:** `docs/design/decisions-v2/05-organizations.md` §2, §3, §9; `06-trust-and-compliance.md` §1–3, §6;
`08-review-resolutions.md` R6, R11, R12 (08 wins); program plan `2026-10-26-decisions-v2-program.md`.

## Global Constraints

- Authorization invariants hold: mandatory deny and review win; unknown facts never widen; authority is proven, never
  claimed. Here: a role, a membership or a domain is only what the server recorded from a verified source.
- Personal mode stays end to end; the org never learns a Personal profile exists (08 R6). No endpoint, console page,
  event or log line visible to an org names an account that is not its member.
- "Admin actions use two-person approval by default … An admin can't approve their own change" (05 §3).
- "Deprovisioning (SCIM delete or suspend) … Target: under 60 seconds" (05 §2).
- "Members sign in to their Managed profile only through SSO; passwords are disabled for Managed profiles" (05 §2).
- Team = Managed with Google Workspace or GitHub org sign-in plus domain verification, no SAML/SCIM; Business adds SAML
  SSO and SCIM (08 R11). Tiers are flags only in O1.
- Posture recorded now (screen lock, OS minimum, no root/jailbreak, app version); gating waits for O2 (06 §6).
- Migrations for sqlite, mysql and postgresql; MySQL ids that differ by case use `utf8mb4_bin`.
- Builds: cargo `-j 4`, narrow `-p`; tests with `XDG_CONFIG_HOME` and `TMPDIR` under `~/Documents/dev/tmp/dv2-o1/`;
  pinned clippy `PATH=$HOME/.rustup/toolchains/1.98.1-x86_64-unknown-linux-gnu/bin:$PATH CARGO_TARGET_DIR=target-198
  cargo clippy -p <crate> -j 4 -- -D warnings`; `cargo fmt`. Never `/tmp`.
- Android: `cd android && env -u ANDROID_SDK_ROOT ANDROID_HOME=$HOME/Android/Sdk ./gradlew --max-workers=4
  :app:testFullDebugUnitTest`. iOS: `scripts/ios-typecheck.sh`; `ios/Core/Generated/reins_core.swift` must match the
  bindings.
- WorkOS is never called in tests (traits or the loopback mock server).
- UI: short copy, real icons (Material Symbols / SF Symbols or the app's glyphs), never emoji; the Next look.
- Commits and PRs never mention AI.

## Review Focus

1. **A directory event for another org's domain** (an IdP admin of org A provisions `ceo@b.com`): must be refused and
   must not touch any existing account. Test: `scim::tests::a_directory_cannot_provision_outside_its_verified_domains`.
2. **An existing Personal account on a newly verified domain:** it stays Personal, is never listed to the org and is
   not captured by SCIM or sign-in. Test: `scim::tests::provisioning_never_binds_an_existing_non_member_account` and
   `gate::tests::an_existing_personal_account_is_not_captured`.
3. **The proposer approving their own pending change** (by re-posting the form, or as a second role): refused. Test:
   `admin::tests::the_proposer_can_never_approve_their_own_change`.
4. **A webhook body claiming a deletion:** must not deprovision anyone by itself (only events read from the WorkOS API
   do). Test: integration `orgs::a_forged_webhook_body_deprovisions_nobody`.
5. **A git push to an org-owned remote with only the Personal profile signed in:** refused with a clear message, never
   sent to the Personal phone. Test: `profiles::tests::an_org_remote_never_goes_to_the_personal_profile` (desktop).

## Security review fixes folded in during the build

- Remotes are normalized before routing (userinfo, port, GitHub aliases, scp form); lookalike hosts stay Personal.
- Removing a member is judged by the target's roles; the last Org owner is never removed or demoted by an admin.
- One verified domain per org is enforced by the database (`reins_org_verified_domains`, primary key `domain`).
- A tenant's WorkOS organization and directory are bound only with WorkOS's confirmation (`org::workos_api`), each to
  one tenant (unique columns); every identity (SSO, Google, GitHub) requires the sign-in's WorkOS `organization_id`
  to match, so org identity never comes from the email domain.
- The directory removing the last owner keeps the owner role, cuts the account off and flags owner recovery; then two
  Security admins together may make a new owner (`org::invariants`, shared by every path).
- The passkey rule is waived only for a sign-in whose gate decision came through the org's verified identity; password
  and API-key refusals for work accounts come only after a correct credential.
