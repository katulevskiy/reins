# Decisions v2 P3: safety nets — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** make the routine destructive steps of coding agents recoverable, so they can be levelled as recoverable:
deletes go to a Reins trash instead of away, destructive git keeps a backup ref first, and file tools keep a snapshot
of what they overwrite. Each net shows in Activity as **Netted · Restore**, restores from the desktop app and the CLI,
and shows read-only on the phones. The replay reports the ask rate with nets.

**Architecture:**
- **Planner (pure, `reins-policy::effects::nets`).** It takes a shell command and its `Context`, and returns a
  `NetPlan`: the rewritten command, the nets it carries, and the analysis before and after nets. The rewrite only
  replaces a **command word**: `rm` → `'<reins>' net run --plan <id> -- rm`, and the same for `git` with a nettable
  subcommand. Every other byte stays, so quoting, expansion, redirections, loops and functions behave exactly as
  before.
  - **Proof of equivalence:** the rewritten text is parsed again (`shell::ast::parse`), the net prefixes are taken
    out, and the result must equal the original syntax tree. If it differs, the plan has no net.
  - **Attribution (which effects are netted):** the original command is analysed with the rewritten command words
    replaced by `:`. Deletes and ref deletes that disappear are the netted ones. Anything still there (`xargs rm`,
    `sh -c 'rm …'`, `find -delete`, `shutil.rmtree`) is not netted, and keeps its level.
- **Runtime (desktop, `reins-desktop::nets`).** `reins net run --plan <id> -- rm|git …` does the effect with the net,
  rm-compatible and git-compatible. It never deletes or rewrites anything it could not net. On a net failure it
  deletes nothing, exits non-zero and records the failure, so the same command is planned without a net next time
  (and is asked at its original level).
- **Hook (`reins-desktop::hooks`).** For a command, the net is planned before the question. The question carries a
  `Net:` line and the netted command (so the approval binds to the netted command's text). When the verdict is
  **Allow**, the netted command goes back to the harness as its new input. For file tools, the snapshot is taken at
  Allow, right before the tool runs.
- **Store.** `$XDG_DATA_HOME/reins/nets/<plan-id>/` (default `~/.local/share/reins/nets`). It holds `plan.json` and
  `items/<n>/{item.json,data}` for trashed paths and snapshots, and `refs.jsonl` for git backup refs
  (`refs/reins/backup/<plan-id>/<n>` in the repository). Retention: trash and snapshots 7 days, refs 30 days.
  Restore: `reins net restore <id>`, and the desktop app's Activity.

**Tech stack:** Rust 1.98.1 (edition 2024), gpui (desktop app), UniFFI (core → Swift/Kotlin), SwiftUI, Compose.

**Spec:** `docs/design/decisions-v2/` 01 §2.3, §2.5, §5, §9.3; 07 §1 (P3); 08 R1, R2 (wins). The program plan is
`2026-10-26-decisions-v2-program.md`, and P0/P1 is in `2026-10-26-dv2-p0-p1.md`.

## Global Constraints

- **A net is applied only when the rewritten command is provably equivalent apart from recoverability.** That means
  the syntax-tree proof above, and a runtime that refuses (deleting nothing) any option or shape it does not model.
- **A net that fails to apply leaves the request at its original level.**
  - Plan time: no plan (or a path not netted), so its effect keeps its level.
  - Run time: nothing is deleted, the failure is recorded, and the next identical command plans without the net.
  - It never runs the un-netted effect as if it were netted.
- **The guard still decides in P3.** Nets go to the harness only with an **Allow** verdict (phone-approved today, or
  Auto once P2's matrix decides). An unmatched command gets no rewrite: a rewrite needs `allow`, which would skip the
  harness's own prompt and widen what runs. P2 decides on `NetPlan::after` when a plan exists, and must fall back to
  the plain analysis when `apply_file_nets` fails (`decided_on_net`).
- **Harness rewrite support** (each harness's current docs):
  - **Claude Code `PreToolUse`:** `hookSpecificOutput.updatedInput` with `permissionDecision: "allow"`. Permission
    rules are evaluated against the new input, and deny/ask rules still apply.
  - **Codex `PreToolUse`:** `updatedInput` (a string `command`), only with `allow`.
  - **Gemini CLI `BeforeTool`:** `hookSpecificOutput.tool_input` (merged over the model's arguments).
  - **Cursor:** shell goes through `beforeShellExecution`, which cannot rewrite. Its `preToolUse` can
    (`updated_input`), but Reins installs it for `Write|Delete` only. So for Cursor, shell nets are advisory (not
    applied, level unchanged). File snapshots work for every harness, because they need no rewrite.
- **Levels with nets** (08 R2: "recoverable" means tracked by git, or a net was actually applied):

  | Effect | Net | Level without → with net |
  |---|---|---|
  | `FileDelete` path in workspace Source, not in git | trash | L3 → L1 |
  | `FileDelete` path in `~` outside the workspace | trash | L3 → L1 (zone still Outside → asked by the matrix) |
  | `FileDelete` in Generated/Scratch | none (no rewrite needed for them, but a mixed `rm` trashes them too) | L0 |
  | `FileDelete` System, Remote or Unknown area | not lowered (the runtime may still trash it) | unchanged |
  | `git worktree remove --force P` | worktree moved to the trash, admin entry removed by git | L3 → L1 |
  | `git clean -f…` | the dry-run list moved to the trash; git clean itself is not run | its delete → L1 |
  | `git branch -D/-d` | backup ref per branch | L1 → L1 (non-default); default branch unchanged |
  | `git reset --hard` | backup ref of HEAD, `git stash create` of the work tree, colliding untracked files trashed | unchanged (L1) |
  | `git push --force…` | backup ref of the remote's old tip, fetched first | unchanged (P1 already assumes it) |
  | file tool write (Write/Edit/apply_patch/Delete) of an existing file in Source or `~` | snapshot | `~` L3 → L1 |

  Certainty never changes with a net, and neither does the floor.
- **Notifications:** a net never notifies. Activity shows it; the phone shows it read-only in the question.
- **Builds and tests:**
  - cargo `-j 4` and narrow `-p`, with a target directory inside this worktree;
  - tests with `XDG_CONFIG_HOME` and `TMPDIR` under `~/Documents/dev/tmp/dv2-p3/`; never `/tmp`, and no test trash
    in `/tmp`;
  - pinned clippy;
  - `cargo fmt`.
- **Commits** are conventional and never mention AI.

## Review Focus

1. **A rewrite that changes meaning.** Look for `rm` as an argument (`echo rm -rf x`, `grep rm`), inside quotes
   (`"a; rm x"`), in a heredoc body, `\rm`, `command rm`, `sudo rm`, `xargs rm`, `rm` as a variable's value, `rm`
   inside `$(…)` or a function body, and `git` aliases. Each must either be rewritten with the tree proof holding, or
   not be rewritten and keep its level. Tests: `nets::rewrite_keeps_the_tree`, `quoting_survives_the_rewrite`,
   `only_command_words_are_rewritten`.
2. **A net path that escapes.** This covers `..`, symlinked parents, a trailing slash on a symlink to a directory, a
   delete of the trash or of an ancestor of it (`rm -rf ~`), an item record edited to point elsewhere, and a restore
   through a parent that became a symlink. Restore re-checks the canonical parent recorded at delete time, refuses to
   overwrite (except snapshots, which keep the current content first), and refuses relative paths or `..`.
3. **Another filesystem.** A path on a different device than the trash is not netted at plan time (`NetFacts`). At
   run time, `EXDEV` deletes nothing and fails closed.
4. **Concurrent deletes.** Two runs of the same plan (a loop), or two plans at once, get unique item directories
   (`create_dir`, no shared index). A path removed by someone else in between gives rm's "No such file" (ignored with
   `-f`).
5. **Disk full.** Failing to write `item.json` or the snapshot deletes nothing, records the failure, and the next
   identical command is planned without the net.
6. **Prompt injection:** agent text never adds a net or lowers a level. Nets come from command words and the
   engine's effects, never from comments or `what`.
7. **Approval binding:** the question's detail carries the netted command. The phone approves that text, and the
   harness gets exactly it.

### Task 3: The git runtime

**Files:** create `crates/reins-desktop/src/nets/git.rs`.

**Interfaces — Produces:** `pub fn git(store: &Store, plan: &str, args: &[OsString]) -> u8`.
- It re-checks the shape with `reins_policy::effects::nettable_git` and refuses (exit 125, nothing run) when it is not
  one.
- Global `-C dir` and `-c k=v` are kept and passed through.
- Per shape:
  - **branch delete:** `rev-parse --verify refs/heads/<b>` (`refs/remotes/<b>` with `-r`), then `update-ref
    refs/reins/backup/<plan>/<n>`, then run git.
  - **reset --hard:** first check that the target resolves. Then back up HEAD's ref, `stash create`, and trash the
    untracked files the target tracks. Run git. If git fails, put the trashed files back.
  - **worktree remove --force:** it must be listed by `worktree list --porcelain`, must not be the main worktree, and
    must not be locked unless `--force` is given twice. Record HEAD (and the branch). Move the directory into the
    trash, then run git (which removes the admin entry of a missing worktree).
  - **clean:** `clean -n` with the same flags (paths C-unquoted), moving each listed path into the trash; prints
    `Removing <p>` unless `-q`; git clean itself does not run.
  - **push --force:** for each destination, `ls-remote --exit-code`: 2 means a new branch (nothing to keep); 0 means
    `fetch --no-tags <remote> +refs/heads/<d>:refs/reins/backup/<plan>/<n>`; anything else means fail closed. Then
    run git.
- Restore:
  - refs: `branch <name>` at the oid, or `<name>-restored-<id>` when the name is taken;
  - reset: `stash store` plus a branch `reins/restore-<id>` at the old HEAD;
  - worktree: `worktree add --no-checkout`, then move the files back, then `reset -q`;
  - push: a local branch `reins/restore-<id>`, never a push.

## What changed while building (for the reviewer)

- **Store:** it lives in the state folder (`~/.local/state/reins/nets`, next to the activity log), not
  `$XDG_DATA_HOME`. Tests stay isolated through `Paths`, and `$REINS_NETS_DIR` overrides it.
- **Below 64 MiB free on the trash's disk, nothing is planned.** A full disk can't keep a copy, or even record that
  a net failed.
- **Scratch deletes are real deletes:** OS temp, `~/.cache`, `[workspace] scratch`. They lose nothing, and moving
  them could cross disks.
- **The phone's net is its own `desktop_ask` argument (`net`), not a `Net:` line in the detail.**
  - Only `reins hook` sets it; `reins ask` can't. The phone reads it only beside a reported rule.
  - A server older than this refuses the argument, so the question is sent again without it.
- **Shadowing.** No net when the script has any of these:
  - a function named like `rm`/`git`, `reins` or its path, or any name with `/`;
  - `eval`, `source`, `.`, `alias`, `unalias`, `enable`, `hash`, `builtin`, `command` or `trap` run anywhere;
  - a command word that isn't literal.

  This costs two netted cases on the replay, on purpose.
- **Advisory nets on Cursor shell and Windows.** Cursor's `beforeShellExecution` can't rewrite. Windows shells
  aren't POSIX, so no rewrite is attempted there.
- **`rm -v` prints one line per operand.** GNU prints one per file inside a directory too.
- **A force push keeps the remote's old tip as of a fetch just before the push.** A commit someone else pushes in
  between isn't covered.
- **In P3 the guard still decides,** so a net goes to the harness only with an approval. P2 decides on
  `NetPlan::after`.
- Replay, on main after the hardening PR (#220): 51 → 38 recorded asks (6.3% → 4.7%), developer 44 → 31 (6.0% →
  4.2%), recall 100%, known false positives 0. The gate asserts nets remove at least a quarter of the developer asks.

## Review round (one round, all items)

- **Worktree removal:** `reins net run` resolves the operand as git does: the path, else a unique ending of a
  worktree's path. It refuses when nothing resolves. The planner nets only a path that is a linked worktree now.
- **Force push:**
  - Each destination is probed on the push URL for `refs/heads/X` and `refs/tags/X`. A tag of that name refuses.
  - The tip is fetched by URL (no remote-tracking ref moves) into the backup ref.
  - Pins are appended after the user's words, one per destination:
    - the kept tip, or "not there" for a new branch;
    - with the user's bare lease or `--force-with-lease=<ref>`, the tracking ref that lease means;
    - none where the user's own `<ref>:<oid>` decides.
  - `--no-force-with-lease` is not a shape the net runs. Several push URLs refuse.
- **Snapshots:** they record their mode and size, and a restore puts the mode back. Plan time skips files a snapshot
  can't copy (`snapshot_max_bytes`).
- **`reins net run` is bound to its plan:**
  - The rewrite names the store (`--store '<root>'`).
  - `net run` refuses without the hook's `plan.json`, after 12 hours, for a program the plan doesn't net, or in a
    folder the plan doesn't list. The list is the request's folder and the literal `cd`/`pushd` targets.
  - Scratch roots and home come from the plan, never from the environment.
  - Commands that set `REINS_*`, `HOME`, `XDG_*`, `PATH` or `GIT_*` are never rewritten. This covers:
    - assignments, `env`, `export` and `local`;
    - `for` variables;
    - `read`/`mapfile`/`readarray`/`wait`/`getopts`/`unset` with such a name in any word, or a name that isn't
      literal;
    - `printf` with any `v` option (`-vNAME`);
    - `declare`/`local`/`typeset`/`export`/`readonly` namerefs (`-n`) or computed names;
    - `set -a` and `set -o allexport`.
  - A netted git runs the git the hook found, with exactly the hook's `GIT_*`, `HOME` and `XDG_*`. Every other
    `GIT_*`, `XDG_*`, `REINS_*` and `HOME` is cleared.
  - A plan is not used up by one run, because a loop runs its words many times. It ends by time instead.
- **Netted only when applied:** the store writes a `ran` marker when it actually keeps something. Activity shows
  Netted · Restore only then, and "Net not applied" otherwise. The phones show the planned net at question time;
  whether it ran isn't synced to them.
- **Quota:** the trash keeps at most a tenth of its disk (`Store::with_quota` in tests).
  - Only expired items may go to make room.
  - What doesn't fit is not netted, and is asked at its own level.
  - Activity shows "Kept copy gone" for a net that ran but keeps nothing any more.
  - The daemon prunes every 10 minutes (hourly stamp); a netted command never prunes.
- **Prune:** read-only trees are made writable and removed. `.pruning` leftovers are retried. Only removals that
  succeed are counted.
- **`reset --hard`:** collisions are read from the target's tree and the index with sets. This covers ignored files
  and a file where git needs a folder, and never walks untracked trees. A restored file whose place git now uses is
  put back beside it (`name.reins-<plan>`).
- **`rm`:** `rm -f ''` exits 0, `file/` on a file is "Not a directory", and a path removed in between is Missing.
- **Restore** is idempotent ("Already restored"). Worktree restores use the same real-parent checks.
- **Replay realism:**
  - Home is its own disk (as on the recording computer), so `/` and `/tmp` are other disks.
  - Only the context's listed worktrees count as worktrees.
  - Numbers after every review fix: 51 → 42 asks (6.3% → 5.2%), developer 44 → 35 (6.0% → 4.7%), recall 221/221.
  - The worktree removals in the history aren't netted in the replay: their folders aren't in the context any more,
    so the corpus can't show they were worktrees.
  - These are projections. P2 (#224) adds asks only, so nets change no decision until a matrix Auto allows. Its hook
    should then decide on `HookNet::plan.after` when a net is planned (and the harness rewrites), and hand back the
    netted command with the allow.
- **`git push --mirror`** (never netted) also pushes `refs/reins/backup/*`. This is documented in the security model.
